# Apple Stage 14 — «Отмена заказа» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The cancel sheet says what each button does — «Оставить заказ» / «Отменить заказ», for a request «Отправить просьбу» under «Попросить отменить заказ № 1042?». The reason is picked from «Заказал не то · Передумал · Долго ждать · Нужен другой адрес · Другое», with «Добавить подробности» and a counter only under 50 left; «Заказал не то» offers «Изменить заказ», «Нужен другой адрес» explains cancelling and repeating. A request's button is grey «Выберите или напишите причину» until there is one. The sheet stays while it sends («Отменяем…»), keeps an error in itself with «Повторить», and says ✓ «Заказ отменён» before it closes; then the page goes to the top, the card changes in 0.26 s, a banner «Заказ № 1042 отменён» stands 4 s above the bar, and the phone buzzes. If shopping starts while the sheet is open it turns into a request in place, keeping the reason; after a lost answer it says «Отмена не подтвердилась», quotes the reason and offers «Отправить ещё раз» under the same key. The first tap above the sheet only hides the keyboard, and a closed sheet keeps its reason while the order is open. A cancelled order shows «Причина: «…»». At large text the buttons stay above the keyboard; a screen reader hears a named field, the chips' state, every outcome, and lands on the heading.

**Architecture:** The server answers a direct cancel's reason on the order as `cancellation_note`, read from the cancel's own history row (no migration). On the client the pure rules — the chips, the composed reason, what blocks a send, which face the sheet shows — live in `application/cancel_draft.dart`; `OrderCancelController` also keeps the draft and remembers whether the unconfirmed send was a request. The sheet becomes a `ConsumerStatefulWidget` that sends through the controller itself and watches the order, so it can switch faces in place; it closes with what happened (`CancelSheetExit`), and the order page then plays the outcome. The edit banner's timing moves into a shared `TimedBanner` that the cancel banner reuses.

**Tech Stack:** Laravel 13 + PostgreSQL, Flutter 3.47.5, flutter_riverpod 3.4.3, go_router 18.1.2; core `announce`, `textScaleAt`, `trimLikeServer`, `failureText`; orders `OrderMutation`, `PeriodicRefresh`; `HapticFeedback`; flutter_test (`tester.takeAnnouncements()`, `meetsGuideline(iOSTapTargetGuideline)`, `NonlinearTextScaler`, `tester.view.viewInsets`, the `SystemChannels.platform` mock for haptics).
