# Staff Stage 1 — The Shopper's Screens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Shopper's area looks and works like the approved drawings 40–47 of `kit/08-sborshchik.dc.html`: a kit list of orders, a staff menu sheet, an order page per state with grouped lines, kit sheets for the purchase, the questions, "Нет товара", the replacement and the completion, and the closing screen with the bag number.

**Architecture:** One small server change: the Shopper's order gives each line's and each replacement's picture (`image_url`), as the Customer's order and the replacement list already do. The client parses the pictures, gains a few shared kit pieces in `core/widgets/kit/` (sheet, button styles, card, note, tag, empty state) that the Courier and panel stages will reuse, and rebuilds `features/shopper/presentation` from focused files. The controllers, the keyed retries, the 10-second refresh and every server rule stay as they are; only the look and the way into each action change.

**Tech Stack:** Laravel 13 + PostgreSQL (one resource), Flutter 3.47.5, Riverpod 3, go_router, `flutter gen-l10n` (template `app_uz.arb`), Montserrat, `KitColors`.

**Spec:** `kit/08-sborshchik.dc.html` in the Claude Design project "BarakaBozor — стиль покупателя", approved by the Owner on 2026-10-21 ("Да"). Frames: 40 мои заказы, 40а заказов нет, 40б меню, 41 новый заказ, 41а заказ принят, 42 сборка, 42а другие состояния товара, 42б всё решено, 43 покупка, 43а цена выше, 43б меньше, чем нужно, 43в проверьте цену, 43г замена или своё, 44 нет товара, 45 замена: поиск, 45а предложить замену, 45б замены не нашлось, 46 завершить сборку?, 46а заказ собран, 47 заказ больше не ваш. The Owner's rule is `DL-97`; the agent's rules are `DL-98`, one item per task.

## Review Focus

1. **A sheet closed while its request runs.** The purchase, "Нет товара", the proposal and the completion each run a request; while it runs the sheet cannot be closed (back, the scrim, the round ×) and its buttons hold, so the answer always lands on a sheet that still shows. Task 5 test: "a running purchase holds its sheet"; Task 6 test: "a running proposal holds its sheet".
2. **The ask state after the Shopper edits a field.** After the server answers `customer_approval_required`, "Спросить клиента" asks about exactly the values it refused; once the Shopper changes the quantity or the price, the sheet returns to "Записать покупку" and the next tap sends a purchase, not a question. Task 5 test: "editing the refused price returns to the purchase".
3. **A stale order and the disabled completion.** "Завершить сборку" is held while the loaded order has open lines; when the loaded order is all resolved but the server still has an open line, the refusal names it. Task 3 test: "the completion is held while lines are open"; Task 3 test "a completion refused for open lines names them" (rewritten).
4. **An order at the extremes.** Thirty lines, three questions (one expired), a replacement, a 160-character wish, a 300-character customer note, 99 999 999 сум, at 320×640 with text ×2 in both languages: nothing overflows; the progress bar still draws one segment per line. Task 4 test: "the shopping page holds at the extremes".
5. **The staff menu for both staff roles.** The shared menu moves into a sheet with the language; Customer mode shows only when offered; the Courier's app bar loses its own language button so the language is not offered twice. Task 2 tests: "the menu sheet holds the language, Customer mode and the way out", "the Courier's app bar holds one menu".
