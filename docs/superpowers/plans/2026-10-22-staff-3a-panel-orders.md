# Staff Stage 3a — The Panel's Orders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The web panel's frame, its board of orders, the order page, the action windows and the staff sign-in look and work like the approved drawings 55–61в of `kit/10-panel-zakazy`, `kit/10b-panel-zakaz`, `kit/10c-panel-okna` and `kit/10d-panel-vhod-uzkiy`.

**Architecture:** Client only. The panel shell gets the kit's side menu in three widths; the board and the order page are rebuilt from focused files on the same controllers, providers and server calls; a kit dialog replaces the Material dialogs; the staff sign-in screens stand on a card on a wide window. The one data change is reading three instants the server already sends (`timestamps.shopping_started_at`, `ready_for_delivery_at`, `on_the_way_at`) for the order's path. Every server rule, every request and every key the behaviour tests use stays.

**Tech Stack:** Flutter 3.47.5, Riverpod 3, go_router, `flutter gen-l10n` (template `app_uz.arb`), Montserrat, `KitColors`.

**Spec:** the Claude Design project "BarakaBozor — стиль покупателя", files `kit/10-panel-zakazy.dc.html` (55 доска; the Owner chose variant А on 2026-10-22), `kit/10b-panel-zakaz.dc.html` (56 заказ, 56а–56и card states), `kit/10c-panel-okna.dc.html` (57–59а windows), `kit/10d-panel-vhod-uzkiy.dc.html` (60–60в sign-in, 61 laptop, 61а–61в tablet), each approved by the Owner ("да", 2026-10-22). Styles in `kit/panel.css`, `kit/panel-zakaz.css`. The Owner's rule is `DL-97`; the agent's rules are `DL-100`, one item per task. Kit pieces this plan reuses are listed in `docs/superpowers/plans/2026-10-21-staff-2-courier-screens.md` Task 1.

Task 6 test "a running action holds its dialog, × included"; Task 4 test "an assignment in flight shows on its button".
