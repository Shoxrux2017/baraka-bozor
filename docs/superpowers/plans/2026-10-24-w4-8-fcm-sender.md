# W4-8 Firebase Cloud Messaging Sender Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The queued pushes of W4-7 reach phones through Firebase Cloud Messaging's HTTP v1 API. A token Firebase refuses for good revokes its device, a transient refusal is retried honouring `Retry-After`, devices unseen for 60 days are revoked nightly, and a production box refuses to start on the fake push driver.

**Architecture:** `FcmPushSender` implements the existing `PushSender` port. It gets its OAuth token from `google/auth` (`ServiceAccountCredentials` behind `FetchAuthTokenCache` with an in-memory pool), whose HTTP goes through Laravel's `Http` client. So tests fake both Google endpoints, and `preventStrayRequests` proves nothing leaves. It maps Firebase's answers onto `PushSendResult`, which gains "revokes the device" and "retry after N seconds". `DeliverPush` acts on both. `ProductionConfiguration` refuses `PUSH_DRIVER=fake` and resolves the sender at boot.

**Tech Stack:** Laravel 13 (PHP 8.4), PostgreSQL, the database queue, PHPUnit, `google/auth` ^1.55 (new).

**Spec:** `docs/DECISIONS.md` `DL-104` (11) and `DL-112`, `tasks/WAVE_4.md` W4-8, `docs/07-architecture.md` sections 24 and 25, `docs/08-database.md` sections 25 and 26. This plan's decisions become `DL-114` (Task 3). They include one correction found while planning. Firebase's documented answer for a bad token, `400 INVALID_ARGUMENT` "The registration token is not a valid FCM registration token" with an `FcmError` detail, names no field. So `DL-104` (11)'s "details name the token field" would never fire on it ([FCM error codes](https://firebase.google.com/docs/cloud-messaging/error-codes)). Task 2 accepts either form. Task 4 checks the real answer on the Owner's project.

## Global Constraints

- Backend commands run inside Compose from the repository root: `docker compose -f docker/compose.yaml exec -T app <command>`. Never run `migrate:fresh`, `db:wipe`, `db:seed` or any `--env=testing` artisan command; `php artisan test` alone touches the test database.
- One new dependency, `google/auth:^1.55` (`composer require` in the container, Task 2). The commit message says why: Google's own library signs the service-account JWT and caches the OAuth token (`DL-104` (11)). `composer.lock` changes only with it. No other dependency, no frontend change.
- Every new PHP file: `declare(strict_types=1);`, `final` classes, the module's namespace `App\Modules\Notifications\...` (commands in `App\Console\Commands`), docblocks in the style of `TelegramGatewayCodeDelivery`.
- No test reaches a network: every FCM test calls `Http::preventStrayRequests()`, and google/auth's requests go through Laravel's `Http`.
- Never logged, returned in an error code, or put in an exception message: the push token, the OAuth access token, the service-account key or its base64, a title or a body. Exception messages name settings, never values. Every parameter that carries the push token or the key is `#[\SensitiveParameter]`.
- Fixed values: scope `https://www.googleapis.com/auth/firebase.messaging`; send URL `https://fcm.googleapis.com/v1/projects/{project_id}/messages:send`; token endpoint `https://oauth2.googleapis.com/token`; both HTTP calls `timeout(10)->connectTimeout(5)`; the one log line is `Log::warning('FCM refused a push.', ['reason' => $code])`.
- The setting is `FCM_SERVICE_ACCOUNT`, the base64 of the Firebase service-account key file, read as `config('services.fcm.service_account')`. The project id comes from the key's `project_id`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A broken template revokes every device.** An `INVALID_ARGUMENT` about the message (a data value, the size, a mixed set of fields) must revoke nothing (Task 2, `test_an_invalid_message_revokes_nothing`).
2. **A secret in a log, an error code or an exception.** This covers the push token, the access token, the private key and the base64 setting, including when the key is malformed (Task 2, `test_no_secret_reaches_a_log_or_a_result`; Task 2, `FcmServiceAccountTest`).
3. **A stale push after an outage.** A `Retry-After` that lands past the hour fails the row now. The TTL Firebase gets is the push's remaining lifetime, so a phone that comes online late gets nothing old (Task 1).
4. **A worker whose cached OAuth token went bad.** A `401` must drop the cached token and retry, not fail pushes until the worker restarts (Task 2, `test_a_401_drops_the_cached_token_and_retries`).
5. **Pruning a device that was never seen, or one already revoked.** `last_seen_at` null falls back to `created_at`. A revoked device keeps its first `revoked_at` (Task 1, prune test).

- [ ] **Step 4: Implement.**

  **Tokens.** The constructor builds `new FetchAuthTokenCache(new ServiceAccountCredentials(self::SCOPE, $account->key()), null, $this->pool = new MemoryCacheItemPool())`. The sender is a container singleton, so a worker process fetches one token an hour. A `401` that is not `THIRD_PARTY_AUTH_ERROR` calls `$this->pool->clear()` and answers retry.

  **The HTTP handler** passed to `fetchAuthToken` is `static function (RequestInterface $request, array $options = []): ResponseInterface`. It replays the PSR request through `Http::timeout(10)->connectTimeout(5)->withHeaders(<request headers without Host>)->withBody((string) $request->getBody(), $request->getHeaderLine('Content-Type'))->send($method, (string) $uri)`. It throws `FcmTokenUnavailable` on `429` or `>= 500`, and otherwise returns `->toPsrResponse()`.

  **Token failures.** `ConnectionException` or `FcmTokenUnavailable` gives `retry('auth_unavailable')`. Any other `\Exception` from google/auth, or an answer without a string `access_token`, gives a logged `failed('auth_failed')`. Never catch `\Error`.

  **Mapping a non-2xx send answer.**
  - `$code` = the FcmError `errorCode` when it matches `^[A-Z_]{1,64}\z`, else `error.status` when it matches, else `http_<status>`.
  - FcmError `UNREGISTERED` gives `rejectedToken('UNREGISTERED')`.
  - `$code === 'INVALID_ARGUMENT'` about the token gives `rejectedToken('invalid_token')`. "About the token" means the BadRequest fields are exactly `['message.token']`. Or, with no field violations, `error.message` contains `registration token is not a valid` (case-insensitive).
  - `429` or `>= 500` gives `retry($code, <Retry-After as delta-seconds or HTTP-date, else null> ?? ($status === 429 ? 60 : null))`.
  - A `401` other than `THIRD_PARTY_AUTH_ERROR` drops the cached token and gives `retry($code)`.
  - Everything else gives `failed($code)` with the warning.

  **The message array** is built inline in `send` from the push token, the title, the body, the data, `android.priority` `high`, `android.ttl` `"{ttlSeconds}s"` and `apns.headers.apns-expiration` = `(string) (now()->getTimestamp() + ttlSeconds)`. Leave out the Android channel: W4-9 names the default channel in the app's manifest.
