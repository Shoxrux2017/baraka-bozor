# Google Play — ваши шаги по порядку

Для владельца проекта. В скобках — английские названия пунктов меню: Play Console может быть на любом языке, а Google иногда переименовывает пункты. Если пункт выглядит иначе, пришлите скриншот.

Файлы рядом: `listing.md` — тексты страницы, `data-safety.ru.md` — анкета безопасности данных, `content-rating.ru.md` — анкета рейтинга. Сборку `.aab` и её `.txt` вам передаёт агент.

## Что должно быть готово до начала

- Сервер работает (W4-5): открываются `https://api.<домен>/legal/privacy` и `https://api.<домен>/account-deletion`.
- На сервере заведён номер для проверяющих Google и его код (`DL-105`), а аккаунт «Проверка Google» создан.
- Аккаунт разработчика Google Play (личный, $25 один раз) прошёл проверку личности.
- Список из 12 и более тестировщиков: адреса Google (Gmail), которыми они входят в Play Маркет на своём Android-телефоне.

- Название инструкции: `Customer sign-in`
- Имя пользователя / телефон (Username): номер проверяющих в виде `+998XXXXXXXXX`
- Пароль (Password): шестизначный код проверяющих из настроек сервера (`LOGIN_CODE_REVIEWER_CODE`). Агент сообщит его вам лично, в репозитории его нет.

## 4. Подпись приложения (Test and release → Setup → App signing)

При первой загрузке Play предложит **подпись приложений Google Play** (Play App Signing): соглашайтесь, ключ создаёт Google. Ваша сборка подписана **ключом загрузки** (upload key). Файл ключа — `G:\tools\secrets\barakabozor-upload.jks`, пароль — в `frontend/android/key.properties`. Скопируйте оба файла в менеджер паролей или на флешку. Если ключ загрузки потеряется, его заменяют через поддержку Google Play; приложение от этого не пострадает.

После первой загрузки на этой странице появятся два отпечатка **SHA-1**: ключа подписи приложения (App signing key certificate) и ключа загрузки (Upload key certificate). Оба нужны в шаге 6.

## 5. Закрытое тестирование (Test and release → Testing → Closed testing)

1. Откройте трек **Closed testing** (по умолчанию «Alpha») → **Управлять треком** (Manage track).
2. Вкладка **Тестировщики** (Testers) → **Создать список адресов** (Create email list): название `BarakaBozor testers`, вставьте 12+ адресов через запятую → **Сохранить**. Отметьте список галочкой. В поле обратной связи укажите ваш email.
3. **Создать выпуск** (Create new release) → загрузите `.aab` от агента. Название выпуска Play подставит сам (`1 (1.0.0)`). Примечания к выпуску (Release notes) — из `listing.md`, раздел «What's new».
4. **Далее** (Next) → **Сохранить** (Save) → **Отправить на проверку** (Send for review). Первая проверка Google занимает от нескольких часов до нескольких дней.
5. Когда выпуск опубликован, на вкладке «Тестировщики» появится **ссылка для участия** (Join on Android / Copy link). Отправьте её тестировщикам. Каждый открывает её на телефоне под тем же Google-аккаунтом, нажимает **Стать тестировщиком** (Become a tester), затем устанавливает приложение из Play Маркета.
6. **14 дней подряд** должно быть не меньше 12 тестировщиков в программе. Если кто-то выйдет и вернётся, его дни считаются заново. Счётчик — на главной странице приложения (Dashboard).

Каждую новую сборку агент собирает с номером версии на 1 больше. Вы загружаете её в тот же трек: **Создать выпуск** → `.aab` → примечания → **Отправить на проверку**. Тестировщики получат обновление через Play Маркет.

## 6. Ключи Google Maps и Firebase (Google Cloud Console)

Без этого шага карта и уведомления в сборке из Play могут не работать.

1. Откройте **console.cloud.google.com** → проект с ключом карт → **APIs & Services → Credentials** (API и сервисы → Учётные данные).
2. Ключ Maps SDK for Android → **Application restrictions: Android apps** (ограничение: приложения Android) → **Add** для каждого отпечатка:
   - пакет `uz.barakabozor.app` + SHA-1 ключа загрузки (агент пришлёт);
   - пакет `uz.barakabozor.app` + SHA-1 ключа подписи Play (шаг 4);
   - пакет `uz.barakabozor.app` + SHA-1 отладочного ключа агента (для сборок разработки; агент пришлёт).
   → **Save**. Изменения действуют до 5 минут.
3. То же для ключа Firebase: проект `barakabozor-a2d8a` → ключ «Android key (auto created by Firebase)».
4. Ключ Geocoding (серверный) ограничивается по IP-адресу сервера — это шаг W4-5.

## 7. Заявка на выход в продакшен (после 14 дней)

**Главная** (Dashboard) → **Подать заявку на доступ к рабочей версии** (Apply for production). Google спросит о тестировании (как набирали тестировщиков, что они нашли), о приложении (для кого, сколько установок ждёте в первый год) и о готовности (что изменили после теста). Ответы агент подготовит к этому дню по итогам пилота. Проверка заявки — обычно до 7 дней.
